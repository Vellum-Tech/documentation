Once you have a populated Document Index, you can retrieve relevant chunks at query time in two ways: by adding a **Search Node** to a Vellum Workflow, or by calling the **Search API** directly from your application code. This page covers both approaches, explains the structure of search results, and shows you how to apply filters to narrow results.

## Using the Search Node in Workflows

The Search Node is a first-class node type in the Vellum Workflow editor. It lets you wire document retrieval directly into your pipeline without writing any code — the retrieved chunks flow naturally into a downstream Prompt Node as context.

<Steps>
  <Step title="Add a Search Node">
    Open your Workflow in the editor. Click the **+** button on the canvas and select **Search** from the node palette.
  </Step>
  <Step title="Select your Document Index">
    In the Search Node's configuration panel, choose the **Document Index** you want to query from the dropdown. Only indexes in the current environment are shown.
  </Step>
  <Step title="Configure the query input">
    Set the **Query** field to the Workflow input variable that contains the user's question (for example, `{{user_message}}`). You can also set **Limit** to control how many chunks are returned (default is 5).
  </Step>
  <Step title="Connect results to a Prompt Node">
    Draw an edge from the Search Node's output to the Prompt Node that will use the retrieved context. In the Prompt Node's template, reference the search results using the output variable — for example, include a system message like:

    ```text
    Use the following context to answer the user's question:
    {{search_results.text}}
    ```
  </Step>
  <Step title="Test the Workflow">
    Use the **Run** panel to send a sample query and verify that the retrieved chunks are relevant before deploying.
  </Step>
</Steps>

## Calling the Search API Directly

If you prefer to retrieve chunks from your own application code — for example, to post-process results or combine them with other data sources before passing them to an LLM — use the Search API.

<CodeGroup>
```python Python
import vellum
import os

client = vellum.Vellum(api_key=os.environ["VELLUM_API_KEY"])

results = client.search(
    index_name="product-docs",
    query="How do I reset my password?",
    options={
        "limit": 5,
        "weights": {
            "semantic_similarity": 0.8,
            "keywords": 0.2,
        },
    },
)

for result in results.results:
    print(result.text)
    print(result.document.label)
    print(result.score)
```

```typescript TypeScript
import { VellumClient } from "vellum-ai";

const client = new VellumClient({ apiKey: process.env.VELLUM_API_KEY });

const results = await client.search({
  indexName: "product-docs",
  query: "How do I reset my password?",
  options: {
    limit: 5,
    weights: {
      semanticSimilarity: 0.8,
      keywords: 0.2,
    },
  },
});

for (const result of results.results) {
  console.log(result.text);
  console.log(result.document.label);
  console.log(result.score);
}
```
</CodeGroup>

## Search Result Format

Each item in the `results` array represents a single chunk that matched your query. The fields returned for each result are:

<ResponseField name="text" type="string" required>
  The raw text of the matching chunk as it was stored in the index.
</ResponseField>

<ResponseField name="score" type="float" required>
  A normalized relevance score between `0` and `1`. Higher values indicate greater semantic similarity to the query. You can use this to filter out low-confidence results by discarding chunks below a threshold (for example, `score < 0.5`).
</ResponseField>

<ResponseField name="document" type="object" required>
  Metadata about the source document the chunk was extracted from.

  <Expandable title="document fields">
    <ResponseField name="document.label" type="string">
      The human-readable label you assigned when uploading the document (for example, `"Product Guide v2.4"`).
    </ResponseField>

    <ResponseField name="document.external_id" type="string">
      An optional identifier you can set at upload time to link Vellum documents back to records in your own system.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="keywords" type="string[]">
  The keywords Vellum extracted from the chunk that contributed to the match when keyword weighting is enabled.
</ResponseField>

## Filtering

### Keyword Filters

You can blend semantic similarity with keyword matching by adjusting the `weights` option. Setting a non-zero weight for `keywords` causes Vellum to perform a hybrid search — semantic vectors are combined with BM25-style keyword scores to produce the final ranking.

```python
results = client.search(
    index_name="product-docs",
    query="SSL certificate renewal",
    options={
        "limit": 5,
        "weights": {
            "semantic_similarity": 0.5,
            "keywords": 0.5,
        },
    },
)
```

### Metadata Filters

If you tagged your documents with metadata at upload time, you can filter results to only chunks belonging to specific documents or categories. Pass a `filters` object in the options:

```python
results = client.search(
    index_name="product-docs",
    query="refund policy",
    options={
        "limit": 5,
        "filters": {
            "external_ids": ["doc-policy-2024", "doc-policy-2023"],
        },
    },
)
```

<Tip>
  Use pure semantic search (high `semantic_similarity` weight) for open-ended conceptual questions where the user may not know the exact terminology. Switch to hybrid or keyword-weighted search when users are looking for specific terms like error codes, product SKUs, or proper nouns — keyword matching ensures those exact tokens contribute to the ranking even if the semantic embedding doesn't capture them strongly.
</Tip>
