Vellum Observability gives you end-to-end visibility into how your deployed prompts and workflows are performing in production. Every API call you make to a Vellum Deployment is automatically recorded as an **Execution log**, capturing the full input and output alongside latency, token usage, cost estimates, and any quality scores computed by your Online Evaluators. You can drill into individual executions for debugging, track aggregate trends over time, and feed end-user feedback signals back into Vellum to close the quality loop.

## Execution Logs

Every time your application calls a Vellum Deployment — whether it's a Prompt Deployment or a Workflow Deployment — Vellum records an **Execution**. Each log entry captures:

| Field | Description |
|---|---|
| **Inputs** | The exact variable values sent with the request (for example, `user_message`, `context`). |
| **Output** | The full text generated by the LLM, or the structured output for workflow executions. |
| **Latency** | End-to-end response time in milliseconds, from request receipt to last token delivered. |
| **Token counts** | Prompt tokens, completion tokens, and total tokens consumed by the execution. |
| **Cost estimate** | Estimated cost of the execution based on the model's published pricing. |
| **Metric scores** | Any quality scores computed by Online Evaluators attached to the deployment. |

Execution logs are retained according to your plan's data retention policy and are available in both the UI and via the API.

<Note>
  Execution logs are environment-scoped. Logs generated by calls using a Production API key appear only in the Production environment, and similarly for Development and Staging. Make sure you are viewing the correct environment when investigating an issue.
</Note>

## Viewing Executions

To browse execution logs in the UI:

1. Navigate to **Deployments** in the left sidebar.
2. Select the Prompt Deployment or Workflow Deployment you want to inspect.
3. Click the **Executions** tab.

The **list view** shows a paginated table of recent executions, with columns for timestamp, latency, token count, estimated cost, and any metric scores. You can sort and filter by these columns — for example, filter to executions with a quality score below a threshold to quickly surface regressions.

Click any row to open the **per-execution drill-down**, which shows:

- The full input variables and rendered prompt (for prompt deployments).
- The complete output text or structured result.
- A token-by-token latency breakdown where available.
- Individual metric scores from each Online Evaluator.
- Any Actuals (end-user feedback) that have been submitted for this execution.

<Tip>
  Use the **search** field on the Executions tab to find a specific execution by its ID. When your application logs execution IDs alongside your own application logs, you can quickly cross-reference production incidents with the exact LLM call that caused them.
</Tip>

## Capturing End-User Feedback (Actuals)

Execution logs record what your LLM produced, but they don't automatically know whether the output was good. **Actuals** let you send end-user feedback signals — thumbs up/down ratings, explicit quality scores, or corrected outputs — back to Vellum so they appear alongside the execution log and feed into quality trend dashboards.

Submit Actuals using the `submit_completion_actuals` method after your application receives feedback from the user:

```python
import vellum
import os

client = vellum.Vellum(api_key=os.environ["VELLUM_API_KEY"])

client.submit_completion_actuals(
    deployment_name="customer-support-bot",
    actuals=[
        {
            "id": "exec_01j4k2m9p8q3r5s6t7u8v9w0x",  # execution ID from the original response
            "quality": 1.0,   # 1.0 = positive, 0.0 = negative
        }
    ],
)
```

You can submit multiple Actuals in a single call by adding more items to the `actuals` list. The `quality` field accepts any float between `0.0` and `1.0`, so you can map star ratings or numeric scores directly.

<Note>
  Actuals are tied to a specific execution by its `id`. Store execution IDs in your application wherever you surface the LLM output to users, so you can correlate feedback to the right log entry later.
</Note>

## Cost and Token Tracking

The **Executions** tab and the deployment's **Analytics** tab both surface token and cost data:

- **Per-execution** — The drill-down view shows prompt tokens, completion tokens, and an estimated cost for that specific call.
- **Aggregate trends** — The Analytics tab plots daily and weekly trends for total token usage and total estimated spend, broken down by model if you use multiple models within a workflow.

Cost estimates are calculated using each model provider's published per-token pricing at the time of the execution. Actual charges are determined by your agreement with the provider and may differ slightly from Vellum's estimates.

## Quality Score Trends

If you have **Online Evaluators** attached to a deployment, Vellum runs them asynchronously against each execution and writes the resulting metric scores back to the log. These scores also appear in aggregate on the deployment's **Analytics** tab as a time-series chart.

Quality score trends let you:

- Detect gradual regressions after a prompt change or model upgrade.
- Compare quality before and after a new deployment release.
- Set up alerts when the rolling average of a metric drops below a threshold.

To configure Online Evaluators for a deployment, navigate to the deployment's **Evaluations** tab and attach one or more evaluators from your Evaluation library.
