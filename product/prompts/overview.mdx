Vellum's Prompt management system gives you a complete lifecycle for LLM prompts — from first draft to production deployment. You iterate in an interactive sandbox, run test cases to validate quality, and deploy to a versioned API endpoint that your application calls. When you update a prompt, you push a new release; your application code never changes.

## The Prompt Sandbox

The Prompt Sandbox is a split-pane editor accessible from the **Prompts** section in the Vellum sidebar.

### What you can do in the sandbox

- **Write system and user prompts** using Jinja-style `{{variable}}` syntax to define dynamic inputs
- **Test with multiple models** side-by-side — compare GPT-4o, Claude 3.5, Gemini 1.5, and others in a single run
- **Add test scenarios** (named input sets) to validate prompt behavior across different cases
- **View token counts and cost estimates** for each run
- **Chat mode** — switch to a conversation view to test multi-turn prompts

### Prompt types

| Type | Best for |
|---|---|
| **Completion** | Single-turn text generation with a system + user prompt |
| **Chat** | Multi-turn conversations using `CHAT_HISTORY` input variables |
| **Structured output** | JSON-schema-constrained responses for classification or extraction |

## Input variables

Prompts accept typed input variables declared in the sandbox. Use double-brace syntax in your prompt template:

```
You are a customer support agent for {{company_name}}.

User question: {{user_query}}

Respond in a {{tone}} tone.
```

The variables `company_name`, `user_query`, and `tone` are declared in the **Input Variables** panel and typed as `STRING`, `NUMBER`, `JSON`, or `CHAT_HISTORY`.

## Model providers

Vellum supports prompts across all major LLM providers:

- **OpenAI** — GPT-4o, GPT-4o Mini, o1, o3
- **Anthropic** — Claude 3.5 Sonnet, Claude 3.5 Haiku, Claude 3 Opus
- **Google** — Gemini 1.5 Pro, Gemini 1.5 Flash
- **Cohere** — Command R+
- **Mistral** — Mistral Large, Mixtral
- **Meta** — Llama 3 (via hosted providers)
- **Custom / self-hosted** — Any OpenAI-compatible endpoint

<Note>Provider credentials are configured in **Settings → Model Providers**. You can use Vellum's managed keys or bring your own.</Note>
