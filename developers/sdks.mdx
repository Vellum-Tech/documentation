Vellum maintains **official SDK clients** for Python, TypeScript/Node.js, and Go. Each SDK is generated from the same OpenAPI spec that drives the REST API, so every endpoint, request shape, and response type is available with full type safety and IDE autocompletion. This page covers installation, client initialization, custom base URLs for self-hosted deployments, async usage, and error handling.

## Installation

Install the SDK for your language using your package manager:

<CodeGroup>
```bash pip (Python)
pip install vellum-ai
```

```bash npm (TypeScript / Node.js)
npm install vellum-ai
```

```bash go get (Go)
go get github.com/vellum-ai/vellum-client-go
```
</CodeGroup>

<Note>
  We recommend pinning to a specific version in production (e.g., `vellum-ai==0.x.y` or `"vellum-ai": "^0.x.y"`) and reviewing the [changelog](#sdk-versioning-and-changelog) before upgrading.
</Note>

## Initializing the client

Pass your API key when constructing the client. The best practice is to read the key from an environment variable rather than hard-coding it.

<Tabs>
  <Tab title="Python">
    ```python
    import os
    import vellum

    client = vellum.Vellum(api_key=os.environ["VELLUM_API_KEY"])
    ```
  </Tab>
  <Tab title="TypeScript">
    ```typescript
    import Vellum from "vellum-ai";

    const client = new Vellum({
      apiKey: process.env.VELLUM_API_KEY,
    });
    ```
  </Tab>
  <Tab title="Go">
    ```go
    package main

    import (
        vellumclient "github.com/vellum-ai/vellum-client-go/client"
        vellumopt "github.com/vellum-ai/vellum-client-go/option"
        "os"
    )

    func main() {
        client := vellumclient.NewClient(
            vellumopt.WithApiKey(os.Getenv("VELLUM_API_KEY")),
        )
        _ = client
    }
    ```
  </Tab>
</Tabs>

The client is safe to instantiate once and reuse across your application. You do not need to create a new client per request.

## Self-hosted / VPC configuration

If your organization runs Vellum in a self-hosted or VPC deployment, pass a custom base URL when initializing the client so all requests are routed to your instance instead of `https://api.vellum.ai`.

<Tabs>
  <Tab title="Python">
    ```python
    from vellum import Vellum, VellumEnvironment

    client = Vellum(
        api_key="your-api-key",
        environment=VellumEnvironment(
            default="https://api.vellum.yourcompany.com",
            predict="https://api.vellum.yourcompany.com",
            documents="https://api.vellum.yourcompany.com",
        ),
    )
    ```
  </Tab>
  <Tab title="TypeScript">
    ```typescript
    import Vellum from "vellum-ai";

    const client = new Vellum({
      apiKey: process.env.VELLUM_API_KEY,
      environment: {
        default: "https://api.vellum.yourcompany.com",
        predict: "https://api.vellum.yourcompany.com",
        documents: "https://api.vellum.yourcompany.com",
      },
    });
    ```
  </Tab>
  <Tab title="Go">
    ```go
    client := vellumclient.NewClient(
        vellumopt.WithApiKey(os.Getenv("VELLUM_API_KEY")),
        vellumopt.WithBaseURL("https://api.vellum.yourcompany.com"),
    )
    ```
  </Tab>
</Tabs>

<Note>
  Contact your Vellum account team to confirm the correct base URL for your deployment. Typically, a single hostname handles all traffic, but some enterprise deployments route `documents` requests to a separate endpoint.
</Note>

## Async clients

<Tabs>
  <Tab title="Python">
    The Python SDK ships an `AsyncVellum` client that mirrors the synchronous API but returns coroutines. Use it with `asyncio` or any async framework (FastAPI, Starlette, etc.):

    ```python
    import asyncio
    import os
    import vellum

    async def main():
        client = vellum.AsyncVellum(api_key=os.environ["VELLUM_API_KEY"])

        result = await client.execute_prompt(
            deployment_name="my-prompt-deployment",
            inputs=[
                vellum.PromptRequestStringInput(
                    name="user_query",
                    value="What is the capital of France?",
                )
            ],
        )
        print(result.outputs)

    asyncio.run(main())
    ```
  </Tab>
  <Tab title="TypeScript">
    The TypeScript SDK is **async by default** — every method returns a `Promise`. Use `await` or `.then()` as you normally would in any Node.js or browser-based async context:

    ```typescript
    import Vellum from "vellum-ai";

    const client = new Vellum({ apiKey: process.env.VELLUM_API_KEY });

    const result = await client.executePrompt({
      deploymentName: "my-prompt-deployment",
      inputs: [
        { name: "user_query", type: "STRING", value: "What is the capital of France?" },
      ],
    });

    console.log(result.outputs);
    ```
  </Tab>
  <Tab title="Go">
    Go uses blocking calls by default. To run requests concurrently, launch them in goroutines:

    ```go
    package main

    import (
        "context"
        "fmt"
        "sync"

        vellumclient "github.com/vellum-ai/vellum-client-go/client"
        vellumopt "github.com/vellum-ai/vellum-client-go/option"
        "os"
    )

    func main() {
        client := vellumclient.NewClient(
            vellumopt.WithApiKey(os.Getenv("VELLUM_API_KEY")),
        )

        var wg sync.WaitGroup
        wg.Add(1)
        go func() {
            defer wg.Done()
            resp, err := client.ExecutePrompt(context.Background(), nil)
            if err != nil {
                fmt.Println("error:", err)
                return
            }
            fmt.Println(resp)
        }()
        wg.Wait()
    }
    ```
  </Tab>
</Tabs>

## Error handling

All three SDKs surface API errors as structured exceptions (Python/TypeScript) or error values (Go) so you can handle failures gracefully.

<Tabs>
  <Tab title="Python">
    ```python
    import os
    import vellum
    from vellum.core import ApiError

    client = vellum.Vellum(api_key=os.environ["VELLUM_API_KEY"])

    try:
        result = client.execute_prompt(
            deployment_name="my-prompt-deployment",
            inputs=[
                vellum.PromptRequestStringInput(
                    name="user_query",
                    value="Hello!",
                )
            ],
        )
        print(result.outputs)
    except ApiError as e:
        print(f"Vellum API error {e.status_code}: {e.body}")
    ```

    Common status codes:

    | Status | Meaning |
    |--------|---------|
    | `400` | Bad request — check your request body shape |
    | `401` | Invalid or missing API key |
    | `404` | Deployment or resource not found |
    | `429` | Rate limit exceeded — back off and retry |
    | `500` | Internal server error — contact support if persistent |
  </Tab>
  <Tab title="TypeScript">
    ```typescript
    import Vellum, { VellumError } from "vellum-ai";

    const client = new Vellum({ apiKey: process.env.VELLUM_API_KEY });

    try {
      const result = await client.executePrompt({
        deploymentName: "my-prompt-deployment",
        inputs: [{ name: "user_query", type: "STRING", value: "Hello!" }],
      });
      console.log(result.outputs);
    } catch (err) {
      if (err instanceof VellumError) {
        console.error(`Vellum API error ${err.statusCode}:`, err.message);
      } else {
        throw err;
      }
    }
    ```
  </Tab>
  <Tab title="Go">
    ```go
    resp, err := client.ExecutePrompt(context.Background(), req)
    if err != nil {
        // err implements the error interface; cast to *core.APIError for status code
        fmt.Println("API error:", err)
        return
    }
    fmt.Println(resp)
    ```
  </Tab>
</Tabs>

<Warning>
  A `401` error almost always means the API key is missing or was passed in the wrong header. Vellum uses `X-API-Key`, not `Authorization: Bearer`. See the [Authentication](/developers/authentication) page for details.
</Warning>

Vellum SDKs follow [Semantic Versioning](https://semver.org/). Patch releases contain bug fixes; minor releases add new endpoints or options; major releases may include breaking changes with a migration guide.
