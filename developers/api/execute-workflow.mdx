title: "Execute Workflow API Reference: POST /v1/execute-workflow"
sidebarTitle: "Execute Workflow"
description: "Invoke a deployed Vellum workflow with input variables and receive outputs from Final Output nodes, plus a unique execution and run ID."
---

The Execute Workflow endpoint runs a fully deployed Vellum workflow end-to-end and returns the values produced by its Final Output nodes. You can call the synchronous endpoint to wait for all outputs at once, or use the streaming variant to receive node execution events in real time — ideal for long-running workflows or progressive UI updates.

## Endpoint

```
POST https://api.vellum.ai/v1/execute-workflow
```

## Authentication

Every request must include your Vellum API key as a request header.

| Header | Value |
|---|---|
| `X-API-Key` | `YOUR_API_KEY` |

---

## Request Body

<ParamField body="workflow_deployment_name" type="string" required>
  The unique name of the workflow deployment to execute. Required when `workflow_deployment_id` is not provided.
</ParamField>

<ParamField body="workflow_deployment_id" type="string">
  The UUID of the workflow deployment to execute. Provide either the name or the ID as an alternative identifier — not both.
</ParamField>

<ParamField body="release_tag" type="string">
  The release tag that identifies which version of the workflow deployment to run. Defaults to `LATEST` when omitted.
</ParamField>

<ParamField body="inputs" type="array" required>
  An array of input variable objects passed into the workflow's Entry node. Each object must include:

  | Field | Type | Description |
  |---|---|---|
  | `name` | string | The variable name as declared in the workflow. |
  | `value` | string \| number \| object | The value to supply for this variable. |
  | `type` | string | One of `STRING`, `NUMBER`, `JSON`, or `CHAT_HISTORY`. |
</ParamField>

<ParamField body="event_types" type="array">
  An optional list of event type strings that filters which events are included in the streaming response. When omitted, all event types are returned. Useful when you only care about specific node types — for example, `["WORKFLOW"]` to receive only workflow-level lifecycle events.
</ParamField>

---

## Response Fields

<ResponseField name="outputs" type="array">
  An array of output objects emitted by the workflow's Final Output nodes. Each object contains:

  | Field | Type | Description |
  |---|---|---|
  | `name` | string | The output name as declared on the Final Output node. |
  | `value` | string \| number \| object | The value produced by this output node. |
  | `type` | string | The output type: `STRING`, `NUMBER`, `JSON`, or `CHAT_HISTORY`. |
</ResponseField>

<ResponseField name="execution_id" type="string">
  A unique identifier for this workflow execution. Use this value when submitting feedback via `/v1/submit-completion-actuals`.
</ResponseField>

<ResponseField name="run_id" type="string">
  An identifier for the specific execution run within the workflow deployment. Useful for cross-referencing individual runs in the Vellum dashboard.
</ResponseField>

## Examples

<CodeGroup>

```bash cURL
curl -X POST https://api.vellum.ai/v1/execute-workflow \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "workflow_deployment_name": "my-workflow",
    "release_tag": "LATEST",
    "inputs": [
      {
        "name": "user_query",
        "value": "Summarize the latest earnings report",
        "type": "STRING"
      },
      {
        "name": "context",
        "value": {"source": "earnings_q3_2024.pdf"},
        "type": "JSON"
      }
    ]
  }'
```

```python Python SDK
from vellum.client import Vellum

client = Vellum(api_key="YOUR_API_KEY")

result = client.execute_workflow(
    workflow_deployment_name="my-workflow",
    release_tag="LATEST",
    inputs=[
        {
            "name": "user_query",
            "value": "Summarize the latest earnings report",
            "type": "STRING",
        },
        {
            "name": "context",
            "value": {"source": "earnings_q3_2024.pdf"},
            "type": "JSON",
        },
    ],
)

for output in result.outputs:
    print(f"{output.name}: {output.value}")

print("execution_id:", result.execution_id)
print("run_id:", result.run_id)
```

</CodeGroup>

**Example Response**

```json
{
  "outputs": [
    {
      "name": "summary",
      "value": "Revenue grew 12% year-over-year, driven by strong cloud segment performance...",
      "type": "STRING"
    },
    {
      "name": "sentiment_score",
      "value": 0.82,
      "type": "NUMBER"
    }
  ],
  "execution_id": "exec_01hxyz5678abcdef",
  "run_id": "run_01hxyz5678ghijkl"
}
```

## Streaming Variant

```
POST https://api.vellum.ai/v1/execute-workflow-stream
```

The streaming endpoint accepts the same request body as `/v1/execute-workflow` but returns a [server-sent events (SSE)](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events) stream. Each event represents a node execution lifecycle update — node started, node completed, output emitted — giving you fine-grained visibility into workflow progress as it runs.

Use `event_types` in the request body to filter the stream to only the event categories you need.

```python
from vellum.client import Vellum

client = Vellum(api_key="YOUR_API_KEY")

for event in client.execute_workflow_stream(
    workflow_deployment_name="my-workflow",
    inputs=[
        {
            "name": "user_query",
            "value": "Summarize the latest earnings report",
            "type": "STRING",
        }
    ],
):
    print(event)
```

**Example stream events**

```
data: {"type": "NODE", "node_type": "PROMPT", "state": "INITIATED", "node_id": "node_abc"}
data: {"type": "NODE", "node_type": "PROMPT", "state": "STREAMING", "delta": "Revenue grew"}
data: {"type": "NODE", "node_type": "PROMPT", "state": "FULFILLED", "output": {"name": "summary", "value": "..."}}
data: {"type": "WORKFLOW", "state": "FULFILLED", "outputs": [...], "execution_id": "exec_01hxyz..."}
```

## Error Codes

| HTTP Status | Code | Description |
|---|---|---|
| `400` | Bad Request | One or more input variables are missing, mistyped, or the request body is malformed. |
| `401` | Unauthorized | The `X-API-Key` header is missing or invalid. |
| `404` | Not Found | No workflow deployment was found matching the provided name or ID. |
| `429` | Too Many Requests | You have exceeded the rate limit for this endpoint. Retry after the duration indicated in the `Retry-After` header. |
| `500` | Internal Server Error | An unexpected error occurred on the Vellum side. Contact support if the issue persists. |
