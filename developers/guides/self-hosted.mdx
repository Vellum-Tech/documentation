Vellum offers a **self-hosted VPC deployment** option for organizations that require their data to remain within their own infrastructure. In a self-hosted setup, all API traffic is routed to endpoints inside your VPC rather than to Vellum's shared cloud. This page explains how to configure the Vellum Python and TypeScript SDKs — and raw HTTP clients — to point to your private instance.

## Finding your base URLs

Your Vellum base URLs are derived from the hostname of your Vellum application. If your application is accessible at:

```
https://app.vellum.yourcompany.com
```

then your API base URL will be:

```
https://api.vellum.yourcompany.com
```

All three Vellum service endpoints — `default`, `predict`, and `documents` — typically share the same base hostname in a standard self-hosted deployment.

<Note>
  The `documents` upload endpoint may use a different subdomain in some self-hosted configurations (for example, `https://documents.vellum.yourcompany.com`). Confirm the correct URLs for all three endpoints with your Vellum administrator before going to production.
</Note>

If you are unsure of your base URLs, contact your Vellum administrator or reach out to [Vellum Support](mailto:support@vellum.ai).

## Configuring the Python SDK

Pass a custom `VellumEnvironment` object when instantiating the client to override the default cloud endpoints:

```python
from vellum import Vellum, VellumEnvironment

client = Vellum(
    api_key="your-api-key",
    environment=VellumEnvironment(
        default="https://api.vellum.yourcompany.com",
        predict="https://api.vellum.yourcompany.com",
        documents="https://api.vellum.yourcompany.com",
    )
)
```

All subsequent calls made through this `client` instance — prompt execution, workflow execution, document upload, and so on — will be routed to your self-hosted endpoints.

<Note>
  Replace `your-api-key` with an API key generated from your self-hosted Vellum instance. API keys from `app.vellum.ai` (the Vellum cloud) will not authenticate against a self-hosted deployment.
</Note>

## Configuring the TypeScript SDK

Pass an `environment` object to the constructor with the same three base URL fields:

```typescript
import Vellum from "vellum-ai";

const client = new Vellum({
  apiKey: "your-api-key",
  environment: {
    default: "https://api.vellum.yourcompany.com",
    predict: "https://api.vellum.yourcompany.com",
    documents: "https://api.vellum.yourcompany.com",
  },
});
```

As with the Python SDK, all methods on this client instance will use your custom endpoints.

## Verifying the connection

After configuring the client, make a lightweight test call to confirm that your SDK can reach the self-hosted instance. Listing your deployments is a good choice — it requires authentication and exercises the `default` endpoint:

<CodeGroup>

```python Python
from vellum import Vellum, VellumEnvironment

client = Vellum(
    api_key="your-api-key",
    environment=VellumEnvironment(
        default="https://api.vellum.yourcompany.com",
        predict="https://api.vellum.yourcompany.com",
        documents="https://api.vellum.yourcompany.com",
    )
)

try:
    deployments = client.deployments.list()
    print(f"Connection successful. Found {len(deployments.results)} deployment(s).")
except Exception as e:
    print(f"Connection failed: {e}")
```

```typescript TypeScript
import Vellum from "vellum-ai";

const client = new Vellum({
  apiKey: "your-api-key",
  environment: {
    default: "https://api.vellum.yourcompany.com",
    predict: "https://api.vellum.yourcompany.com",
    documents: "https://api.vellum.yourcompany.com",
  },
});

async function verifyConnection() {
  try {
    const deployments = await client.deployments.list();
    console.log(`Connection successful. Found ${deployments.results.length} deployment(s).`);
  } catch (error) {
    console.error("Connection failed:", error);
  }
}

verifyConnection();
```

</CodeGroup>

If the call succeeds, your SDK is correctly configured. If you receive a connection error or an authentication failure, double-check:

- That the base URL is reachable from your network (firewall rules, VPN, private DNS).
- That you are using an API key generated from the self-hosted instance, not the Vellum cloud.
- That the URL does not include a trailing slash.

<Warning>
  If you receive TLS/SSL errors, your self-hosted deployment may use an internal certificate authority. Work with your infrastructure team to trust the appropriate CA certificate in your runtime environment.
</Warning>

## Feature parity

Most Vellum features are available in self-hosted deployments, including:

- Prompt and workflow execution
- Evaluations and Test Suites
- Document indexes and retrieval
- Deployments and release management
- The Vellum UI (Sandboxes, Playground, Monitoring)

Some cloud-specific integrations may behave differently or require additional configuration in a self-hosted environment. This includes certain third-party model provider integrations and features that depend on Vellum's shared infrastructure. Contact [Vellum Support](mailto:support@vellum.ai) for a full list of any limitations that apply to your deployment tier.
