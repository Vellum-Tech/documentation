**Libraries** is your firm's shared knowledge base. Every report number Vellum
produces is computed by the calculation engine from versioned, cited values,
and the libraries are where those values, phrases and methods are curated so
each new project starts from the same defensible foundation.

Open **Libraries** in the sidebar to see the card grid. Each card names a
library, describes what it holds, and shows how many entries it has. Click a
card to open that library's list.

![The Libraries page showing nine library cards with entry counts](/images/libraries/libraries-overview.jpg)

## What "governed" means

Library entries are shared across every organisation and project in your
firm's workspace. They are not project data: a factor, phrase or template you
curate once is reused everywhere, and each library tracks a status on its
entries (for example **Draft**, **Curated** and **Archived**) so everyone can
tell a vetted entry from a work in progress.

<Note>
Creating and editing library entries is staff only. Client organisation
members can benefit from the libraries through their projects, but the
create and edit controls do not appear for them. Policy activation is
further restricted to library curators; see
[Policy library](/libraries/policies).
</Note>

## How the libraries feed projects

- **Phrases seed impact accounts.** The outcome, activity and beneficiary
  libraries hold governed wording that projects draw on when building their
  impact accounts, so the same change is described the same way everywhere.
- **Factors and formulas feed the engine.** The Workbench binds a formula's
  operands to library factors or client data, and the engine computes every
  figure from those versioned, cited values. No one types a dollar figure
  into a report. See [Workbench](/projects/workbench).
- **Policies align reports.** The policy library holds the acts, strategies
  and grant programmes a project's work can align with, each with an archived
  copy of its source, ready for the report's policy alignment block. See
  [Report builder](/projects/report-builder).
- **Methodologies frame the work.** A project chooses its reporting
  methodology on the project record, and the curated valuation methods
  describe how outcomes are valued one level above the formulas.

## The nine libraries

| Library | What it holds |
|---|---|
| [Factor library](/libraries/factors) | Published reference values (prices, rates, wages) reused across clients |
| [Outcome library](/libraries/outcomes) | Governed aligned-outcome phrases that seed impact accounts |
| [Activity library](/libraries/activities) | Governed activity phrases that seed impact accounts |
| [Beneficiary library](/libraries/beneficiaries) | Governed beneficiary groups with consent safeguards |
| [Survey library](/libraries/surveys) | Governed survey templates that turn outcome gaps into evidence |
| [Policy library](/libraries/policies) | Government acts, policies, strategies and grant programmes a project's work can align with |
| [Formula library](/libraries/formulas) | The actual calculations: engine-governed formulas, freely growable |
| [Valuation methodology library](/libraries/valuation-methodologies) | Curated valuation methods: impact values and accounting measures, never blended |
| [Reporting methodology library](/libraries/reporting-methodologies) | The report-level methodologies chosen before outcome valuation |

The wording above follows each card in the app, with punctuation adapted for
this help centre.
